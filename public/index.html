What is this tool for?

Open-weight LLMs come in many compressed (quantized) versions: FP8, INT8, GPTQ, AWQ, NF4 and a dozen GGUF levels. This planner answers the practical question: which version should I run, how big is it, does it fit my GPU, how much precision do I lose — and why?

1

Load any open model

By Hugging Face ID, a file on your computer, a direct link, your local Ollama / LM Studio server, a pasted config.json or just “70B”. Parameter counts are read exactly from the weight files when possible.

2

Size & GPU fit

See the size of every common format side by side and which GPUs each one fits on — and the ready-made quantized versions that already exist on Hugging Face.

3

Measure precision loss

Quantize generated or real weights from the model and see the damage: SQNR, error histograms, how many levels are used, and what clipping or smaller groups would fix.

4

Find sensitive layers

Scan every weight matrix, rank them by how much 4-bit quantization hurts, and get a mixed-precision plan with its exact size.

5

Learn the maths

Every number has a hover explanation with the formula and your actual values. A bit inspector shows how each weight is stored, bit by bit.

6

Private & free

Everything runs in your browser. Files stay on your device, tokens stay in memory, and only small slices of weight files are ever read.

What this tool does not do

  • It does not run the model or measure answer quality. Weight error is a strong hint, not proof. Always check a quantized model on your own tasks (or a benchmark like perplexity / MMLU) before relying on it.
  • It does not quantize or download the full model. To actually produce a quantized model use AutoAWQ, GPTQModel / AutoGPTQ, bitsandbytes, llm-compressor or llama.cpp's llama-quantize.
  • It does not support API-only models (GPT-4, Claude, Gemini…): their weights are not public.
  • Memory for the KV cache and activations is not included in the GPU-fit check. Long contexts and big batches need a lot more than the weights alone.
  • Real GPTQ / AWQ methods also use calibration data to pick their rounding; this tool simulates plain round-to-nearest, so real GPTQ / AWQ results are usually somewhat better than shown.

How to use this tool

  1. Load a model. Paste a Hugging Face ID such as Qwen/Qwen2.5-7B-Instruct into the quick-start box and press Import. For gated models (Llama, Gemma) add your token, or paste the model's config.json instead.
  2. Read the overview. Check the parameter count and where it came from (“exact, from safetensors headers” beats “estimated from config.json”).
  3. Pick a size. In the size table, find the formats that fit your GPU. Move the usable memory slider to leave room for the KV cache.
  4. Check ready-made versions. If someone already published the format you want, use it — no need to quantize yourself.
  5. Measure the precision loss. In the explorer, choose Real layer, pick a big matrix (e.g. layers.0.mlp.down_proj) and load a sample. Switch formats and group sizes and watch SQNR and the charts. Generated weights work without any model.
  6. Scan all layers (Hugging Face or local files) to find the most sensitive tensors and get a mixed-precision plan.
  7. Share or export. Copy a link to the exact setup, download the report and charts, or copy a plain-text summary to paste into an AI assistant.

Reading SQNR (rough guide)

Above 30 dBError is tiny — practically the same weights. INT8 and FP8 usually land at 31–41 dB.
20 – 30 dBSmall error: 5–6 bit formats, or 4-bit with small groups on well-behaved layers.
12 – 20 dBModerate — typical 4-bit territory. INT4 group 128 measured 15–19 dB on every layer of Qwen3-8B. Large models usually cope well; small models suffer more.
Below 12 dBHeavy damage. Expect quality loss; try smaller groups, clipping or more bits.

These bands are a rule of thumb for the weights alone, not a promise about answer quality.

How the maths works

Integer quantization

  • Symmetric: qmax = 2^(b−1) − 1, scale = clipMax ÷ qmax, q = clamp(round(w ÷ scale), −qmax, qmax), stored value w′ = q × scale.
  • Asymmetric: scale = (max − min) ÷ (2^b − 1), zp = round(−min ÷ scale), q = clamp(round(w ÷ scale) + zp, 0, 2^b − 1), w′ = (q − zp) × scale.
  • Rounding is round-half-to-even. Scales are rounded to FP16 (or FP32) because that's how they are stored.

Float formats (FP16, BF16, FP8, FP4)

  • One generic rounding function: e = max(floor(log2|x|), 1 − bias), step = 2^(e − mantissaBits), r = roundHalfEven(|x| ÷ step) × step, saturating at the format's max.
  • FP16 (5e/10m, max 65504) · BF16 (8e/7m) · FP8 E4M3 (bias 7, max 448) · FP8 E5M2 (max 57344) · FP4 E2M1 (±0, 0.5, 1, 1.5, 2, 3, 4, 6).
  • FP8 / FP4 use a scale = absmax ÷ format max. Verified bit-for-bit against PyTorch.
  • NF4: divide each group of 64 by its absmax and snap to the nearest of 16 fixed levels from bitsandbytes.

Memory

  • effective bits = b + scaleBits ÷ groupSize (+ zeroPointBits ÷ groupSize if asymmetric). INT4 group 128 with FP16 scales = 4 + 16/128 = 4.125 bits.
  • size (GB) = parameters × effective bits ÷ 8 ÷ 10⁹.
  • GGUF sizes use bits-per-weight measured by llama.cpp on Llama-3.1-8B (approximate for other models).
  • Fits = weights ≤ usable share (default 85%) of the GPU's memory. GPU sizes are in GiB as sold (a “24 GB” card holds 25.8 × 10⁹ bytes).

Metrics

  • SQNR = 10 · log10(Σw² ÷ Σ(w − w′)²) dB — signal power over error power. Each extra bit adds ≈ 6 dB.
  • MSE / RMSE: average squared error and its square root. Max error: the single worst weight.
  • Cosine similarity: how closely the quantized matrix points in the same direction as the original (1 = identical).
  • Clipped: weights outside the clip range. Zeroed: non-zero weights that became exactly 0. Levels used: how many of the format's values actually appear.

Parameter counts

  • Preferred, exact: Hugging Face's safetensors count, then the safetensors headers (sum of shape products), then a GGUF header.
  • Packed GPTQ / AWQ tensors (qweight) hold 8 four-bit values per int32; they are unpacked, and scales, qzeros, g_idx are not counted.
  • From config.json (Llama-style): attention H·H + 2·H·(kv·head_dim) + H·H, gated MLP 3·H·I, norms, embeddings (+ output head unless tied). MoE counts all experts (total) and only the routed ones per token (active).

Real weights & safety limits

  • Only headers and small slices are read (HTTP Range requests or File.slice()). A sample is several evenly spaced blocks of whole rows.
  • Limits: at most 1,048,576 values per tensor, 4 parallel requests, and you are asked before any scan above 100 MB. Everything can be cancelled.
  • All calculations run in a background Web Worker, so the page never freezes.
